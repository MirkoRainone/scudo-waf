Domande Frequenti (FAQ)

Scudo WAF viene eseguito direttamente nel processo Python del tuo server senza dipendere da proxy esterni. Se la telemetria cloud non è raggiungibile o si verifica un'anomalia imprevista nell'engine, il middleware entra automaticamente in modalità Fail-Open lasciando fluire il traffico applicativo senza causare downtime.

No per tutto il traffico lecito: il modello ML (TF-IDF + CalibratedLinearSVC) e le regole Regex vengono valutati interamente nella tua RAM locale. Nei rari eventi di attacco inviati alla console di telemetria, il payload viene troncato e filtrato dal PII Redactor (mascherando email, carte, IBAN e segreti).

Supporto nativo per FastAPI / Starlette (WafMiddleware ASGI), Flask (ScudoFlask(app)), Django (ScudoDjangoMiddleware) e pipeline LLM (PromptGuard). Per applicazioni Node.js, Go o PHP è incluso il proxy CLI scudo-waf proxy.

Certamente: impostando mode="monitor" nel middleware, Scudo analizza e registra tutte le anomalie rilevate senza restituire HTTP 403. È l'approccio raccomandato per validare l'assenza totale di falsi positivi prima di passare a mode="block".
